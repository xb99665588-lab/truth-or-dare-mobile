# 抽题交互精简设计

## 目标

简化手机端抽题流程，让用户点击真心话、随机或大冒险后，题目直接显示在现有题目方框中，不再进入需要“换一个”或“完成了”的二次操作状态。

## 界面设计

- 在题目方框下方常驻三个并排按钮，顺序固定为“真心话”“随机”“大冒险”。
- “随机”按钮位于“真心话”和“大冒险”之间。
- 删除原有的“随机来一个”长按钮。
- 删除抽题后的“换一个”和“完成了”按钮。
- 三个抽题按钮在题目显示前后都保持可见，用户再次点击即可直接换题。
- 删除顶部完成次数统计，因为不再提供“完成了”操作。

## 交互与数据

- 点击“真心话”时，从当前模式和难度对应的真心话题目中抽取一题。
- 点击“大冒险”时，从当前模式和难度对应的大冒险题目中抽取一题。
- 点击“随机”时，先等概率选择真心话或大冒险，再从对应题库抽取一题。
- 新题直接替换题目方框中的内容，并保留现有切换动画。
- 最近抽取过的 50 道题不重复；不足 50 道的题池沿用现有安全回退逻辑。
- 模式或难度变化后，清空当前题目，但保留抽题按钮。
- 本地存储仅保留模式和难度，不再保存完成次数。
- 转盘功能保持不变，转盘结束后仍将结果直接显示在题目方框中。

## 样式

- 三个按钮采用适合手机窄屏的等宽三列布局。
- 中间“随机”按钮具有独立但协调的视觉样式，按钮文字统一使用短名称。
- 保持现有页面配色、圆角、触控尺寸和手机端布局体系。

## 验证

- 自动测试确认页面不再出现“换一个”“完成了”和“随机来一个”。
- 自动测试确认三个按钮按“真心话”“随机”“大冒险”顺序存在。
- 单元测试确认防重复历史上限从 20 改为 50。
- 运行完整单元测试、页面渲染测试、代码检查和 GitHub Pages 静态构建。
- 在手机尺寸下检查按钮布局、题目更新和线上静态资源加载。
